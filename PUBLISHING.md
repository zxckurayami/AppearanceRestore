# Публикация Appearance Restore

## Первая публикация через браузер

1. Откройте https://marketplace.visualstudio.com/manage и войдите в Microsoft-аккаунт.
2. Выберите существующего или создайте издателя (publisher) с ID `zxckurayami`.
   Этот ID указан в текущем VSIX.
   Чтобы опубликовать именно этот файл, издатель должен иметь такой же ID.
   Доступность ID заранее не проверена. Отображаемое имя издателя может отличаться.
3. Если нужен другой ID или текущий занят, сначала измените `publisher` в
   `package.json` и пересоберите VSIX. Нельзя исправить ID внутри уже собранного
   файла через форму загрузки. ID издателя после создания неизменяемый.
4. На странице издателя выберите New extension, затем Visual Studio Code.
5. Загрузите актуальный VSIX из `dist`, проверьте карточку и отправьте
   расширение на публикацию. Дождитесь результата проверки Marketplace.
   Сам факт локальной сборки не гарантирует одобрения.

Для ручной загрузки через браузер персональный токен доступа (PAT) не нужен.
Никому не передавайте пароль Microsoft-аккаунта или токены.

## Важно про установленную локальную версию

Идентификатор сборки для публикации: `zxckurayami.appearance-restore`.
Ранее локально установлена версия `zxckurayami-local.appearance-restore`.
Сохранение `publisher` и `name` сохраняет идентичность расширения. Другой
издатель означает отдельное расширение с отдельным хранилищем настроек и копий.
Не удаляйте старые резервные копии при смене издателя.
Не оставляйте обе версии включёнными одновременно: команды и напоминания
могут конфликтовать. При пересборке старая установленная версия и её данные
не изменялись; перенос хранилища автоматически не выполняется.

До публикации нужно самостоятельно войти в аккаунт с доступом к издателю
`zxckurayami`. Доступ к аккаунту и публикация не выполнялись при локальной сборке.

## Последующие обновления

1. Увеличьте `version` в `package.json`, например до `1.1.3`, и обновите
   имя выходного файла в скрипте `package`. Дополните `CHANGELOG.md`.
2. Выполните `npm test`, затем `npm run package`.
3. В Marketplace откройте существующее расширение и выберите More Actions,
   затем Update. Загрузите новый VSIX с увеличенной версией.
4. Не создавайте новую карточку для каждого обновления. Сохраняйте `name`
   и `publisher`. Пользователи с включённым автообновлением будут получать
   опубликованные обновления через Marketplace.

Загружайте только VSIX. Не загружайте папку проекта, локальные резервные копии,
настройки редактора или изображения пользователя. В пакет включаются README,
MIT-лицензия, журнал изменений, код расширения и его иконка.
Сторонние расширения и их изображения в пакет не включаются.

Публичный репозиторий: https://github.com/zxckurayami/AppearanceRestore
Ссылки на исходники, README и Issues уже указаны в манифесте.

## GitHub Releases

Готовые VSIX и их SHA-256 публикуются отдельно в Releases, а не коммитятся
в исходники. Описание релиза хранится в `docs/releases/`. GitHub Actions
проверяет исходники на трёх системах и собирает VSIX, но не публикует ничего
в Marketplace и не требует токенов публикации в репозитории.
